# electerm 极简终端定制方案

审查日期：2026-11-16。
本地仓库：`D:\share\electerm\electerm`。
审查基线：版本 `5.11.8`，提交 `0b3bd8e9`。
本轮仅审查与制定方案，没有修改程序源码，没有生成安装包。

## 一、建议结论

基于现有 Electron + React + xterm + node-pty + SSH 实现做减法，不建议第一版更换技术栈。

目标是一个工作方式接近 MobaXterm 的 macOS ARM64 终端，核心仅保留：

- 本机 zsh 终端。
- SSH 终端及其密码、密钥、Agent、MFA、主机指纹验证。
- SSH 跳板机、代理、端口转发。
- 左侧可折叠 SFTP 远程文件浏览及上传、下载。
- 会话分组、搜索、连接历史、多标签、基本分屏。
- 复制粘贴、终端内搜索、字体、编码、按需保存会话日志。
- 本地会话导入、导出和必要的安全设置。

Telnet 和串口也属于终端功能，并非“无关功能”；但按本次最精简目标，建议首版不打包，只有确认实际需要时再保留。

这里的“像 MobaXterm”指终端工作流，不是移植其完整 Windows 工具箱，也不承诺所有功能与快捷键完全一致。

## 二、七项需求：原来与修改后

| 项目 | 当前实现 | 建议修改后 |
| --- | --- | --- |
| 背景 | 未设置背景图片时，主动绘制 electerm 水印 | 固定不透明 `#000000` 终端背景，无水印、图片、文字和随机图案 |
| 连接稳定性 | 前端终端 WebSocket 断开即销毁后端终端；自动重连是重建会话 | 区分显示通道断开与真实会话退出；短暂本地通道故障可重新挂接，真实 SSH 断线再重连 |
| AI | AI 聊天、命令建议、Agent 工具调用、配置和后端请求接口 | 从入口、状态、IPC、后端、依赖和安装包移除，不只是隐藏按钮 |
| 资源 | Electron 固定开销，加上每会话一个后端进程、终端插件、文件浏览等 | 先测量，再裁模块、减少隐式工作、按需加载；进程池作为后续有数据支撑的优化 |
| SFTP | SSH/SFTP 标签切换或自适应分屏，终端在前、文件在后；文件区内部又分本地/远程两栏 | 单一左侧远程文件侧栏，默认展开，可拖宽、收起，随当前 SSH 标签切换 |
| MobaXterm 习惯 | electerm 自有布局、侧栏、底栏与快捷操作组织方式 | 精简工具栏、左侧 Sessions/SFTP、右侧终端标签；增加 MobaXterm 操作预设与会话迁移 |
| 功能范围 | 多协议终端、远程桌面、浏览器、AI、插件、同步等综合工具 | 严格限定为 Local + SSH + SFTP，非必要入口、协议、服务和依赖一并退出发布产物 |

## 四、断连：已确认的机制与尚未确认的根因

### 4.1 目前不能下的结论

没有用户发生断连时的日志、准确时间和运行环境，不能认定此次断连已经找到唯一原因。
本机终端也断开，使共享的本地通信、会话生命周期、Shell 自身退出和应用异常处理成为重点。
SSH 侧的网络、服务器策略仍需独立排查。

未发现本机终端存在“运行若干分钟就主动关闭”的通用空闲定时器。
`session-server.js:770` 的两分钟定时器只清理从未建立过终端 WebSocket 的进程，不是已经连上的终端两分钟空闲就断。

### 4.2 已确认：本地显示连接关闭会杀掉真实会话

当前主要链路：

```text
前端 xterm
  -> 本地终端 WebSocket
  -> 每会话 session-server 子进程
  -> 本机 PTY 或 SSH 连接
```

`src/app/server/session-server.js:530` 将 WebSocket 的 `close` 绑定到 `onClose()`；
该函数在第 452 行调用 `term.kill()`，随后清理进程。

这表示：即使底层 SSH 或本机 Shell 原本仍然正常，只要本地显示连接关闭，也会被真正销毁。
这是可确认的可靠性风险，但还不能证明用户此次一定由它触发。

建议：

- 显式关闭标签、Shell 退出、SSH 断线与前端暂时脱离，使用不同的处理路径。
- 本地显示连接意外关闭时进入短暂 detached 状态，例如 30 秒，允许同一会话身份重新挂接。
- detached 期间输出缓存必须有上限，超限行为可观测；不能无限驻留或无限累积。
- 没有活动传输、且宽限到期后才回收孤立会话；显式退出应用仍立即清理全部子进程。
- 重新挂接查询并复用既有会话，不能继续走“创建新进程”的连接接口。
- 验证旧 WebSocket 的延迟回调不能关闭新 WebSocket 或新会话。
- 保留现有 token 验证、会话所有权和监听本机地址等限制。

### 4.3 已验证：旧进程退出可能删除新会话索引

位置：`src/app/server/session-process.js:245` 和 `:264`。

同一标签重建会话时：

1. 创建新进程。
2. 结束旧进程。
3. 把新进程写入同一个 `pid` 对应的 Map。
4. 旧进程的延迟 `exit` 回调无条件 `activeTerminals.delete(pid)`。

通过加载原文件、模拟子进程事件顺序的独立检查，确认第 4 步可以删除新进程的索引。
这影响后续查找、resize、命令请求与清理；它不等于已证明是首次空闲断线的起因。

修复应校验 Map 当前条目的 `child` 是否仍是退出的那个进程，再决定删除。
新增回归测试，覆盖旧进程延迟退出、快速连续重连和连接测试失败后的清理。

### 4.4 协议保活与输入型保活必须分开

SSH 协议保活已经存在：

- `src/client/common/default-setting.js:50`：间隔 `10000` 毫秒。
- 同文件第 34 行：`keepaliveCountMax: 10`。
- `src/app/server/session-ssh.js:1055`：这些参数被传入 SSH 客户端。

因此不能简单归因为“没有开启 SSH keepalive”。
`sshReadyTimeout` 是建连阶段的超时，也不应被误当作已连接后的空闲超时。

另一个界面“保活”功能不同：

- `src/client/components/terminal/attach-addon-custom.js:166`：按约 3 秒周期检查。
- 同文件 `:743` 附近：空闲时发送自定义 `keepalive` 消息。
- `src/app/server/session-server.js:496`：后端实际向 PTY 写入换行及控制字符。

它意在重置 Shell 的输入空闲计时，不是无副作用的网络心跳。
现有代码已防护密码提示、未提交命令和全屏程序，但极简版仍建议默认不提供自动输入。
不擅自绕过公司服务器的空闲退出策略，也不自动修改服务器配置。

建议首版保留现有 SSH 协议保活参数，先记录真实故障，再调整；本机 PTY 不需要 SSH 保活。

### 4.5 重连与睡眠恢复

- `src/client/common/default-setting.js:90`：自动重连默认关闭。
- `src/client/components/terminal/mixins/term-socket.js:446`：自动重连通过 `reloadTab()` 重建会话。
- `src/client/common/fetch-from-server.js:28`：现有唤醒事件只触发公共通信 WebSocket 初始化。
- 会话子进程遇到未捕获异常或未处理 Promise 拒绝会执行清理退出。

建议增加统一会话状态：
`connecting / connected / detached / reconnecting / disconnected / exited`。

本机 PTY 尚存时只重挂显示通道，不自动新开 Shell。
SSH 确认已断时采用有上限的退避重连，允许取消，用户退出和认证失败不无限重试。
睡眠唤醒后核查每个真实会话，而不是仅依据旧 WebSocket 标志判断健康。

重连不保证原远程进程继续运行；重要长任务可由用户选择 tmux 管理。
重放历史文字也不等于恢复原进程，界面不能混淆这两件事。

### 4.6 排查与验收

记录会话 ID、时间、最近输入输出时间、WebSocket code/reason、Shell exit code/signal、
SSH error/close、子进程退出和系统睡眠/唤醒事件。日志脱敏，不记录密码、私钥或默认保存完整终端内容。

验证矩阵：

- 本机和 SSH 各空闲 30 分钟、2 小时、8 小时。
- 锁屏、最小化、切标签与合盖睡眠后唤醒。
- Wi-Fi 切换、VPN 重连、SSH 服务端关闭连接。
- Shell 设置空闲退出、用户主动 exit、Shell 异常退出。
- 文件上传下载中折叠侧栏、切标签与连接故障。
- 持续大输出、快速关闭重连与重复建立连接。

纯粹的渲染失败必须降级渲染，不应为恢复显示而重建正常会话。

## 五、AI 是什么，怎么删除

它不是 SSH 必需功能，也不是本地内置模型。

当前代码提供调用外部 LLM API 的聊天、选中文字解释、命令建议以及 Agent 工具调用。
Agent 工具包括读取终端输出、发送终端命令、创建和管理标签等。
当前默认设置还包含第三方 API 服务地址。
这不代表已经证实程序在用户不操作时自动上传全部终端内容。

主要位置：

- `src/client/components/footer/footer-entry.jsx:123`：底栏 AI 入口。
- `src/client/components/main/main.jsx:38`、`:381`：AI 面板导入和渲染。
- `src/client/components/ai/`：聊天、配置、Agent、工具定义。
- `src/client/components/terminal/mixins/term-context-menu.jsx`：终端右键 AI 项。
- `src/client/common/ai-feature.js`：已有界面禁用开关。
- `src/app/lib/ipc.js:103`、`:334`：主进程 AI 函数及分发。
- `src/app/lib/ai.js`：外部请求和流式响应管理。
- `src/client/store/mcp-handler.js` 与 `src/app/mcp/`：外部工具控制相关逻辑。

已有禁用开关适合临时预览，不满足最终极简安装包要求。
最终应删除这些模块的可达入口、后台能力、配置项与状态持久化，并检查发布产物中不再含相关模块。
共享库如 axios 不能因为 AI 使用它就直接删除，必须先检查剩余 SSH/SFTP 相关路径是否仍依赖它。
旧版本 AI 历史可不再加载；删除磁盘中的旧用户数据应另行确认，不擅自清空。

## 六、SFTP 与 MobaXterm 风格工作流

### 6.1 现在的结构

`src/client/components/session/session.jsx`：

- 默认 `sshSftpSplitView` 关闭。
- 第 49 行分屏初始为 50/50。
- 第 99 行按窗口比例选择左右或上下排列。
- 第 596/599 行先放终端、再放 SFTP。

`src/client/components/sftp/sftp-entry.jsx:1408`：

- 远程会话的文件区还会并排渲染本地与远程文件列表。
- `initData()` 会初始化远程数据和本地列表；仅隐藏界面不等于不做初始化工作。

所以仅把两个面板交换位置，还不能得到轻量的 MobaXterm 式侧栏。

### 6.2 建议目标布局

```text
+----------------------------------------------------------+
| 新建连接   本机终端   重连   分屏                 设置     |
+------------------+---------------------------------------+
| Sessions | SFTP  | server-a | server-b | local           |
|------------------+---------------------------------------|
| 侧栏内容         |                                       |
| 会话树或远程目录 |            黑色终端                   |
|                  |                                       |
|                  |                                       |
+------------------+---------------------------------------+
| 按需显示的传输进度 / 简要连接状态                         |
+----------------------------------------------------------+
```

设计约定：

- 左侧只保留一个共享 dock，Sessions 和 SFTP 切换，不叠两套侧栏。
- SFTP 默认约 300px，可在合理范围拖动并记忆宽度，收起后终端占满可用宽度。
- 连 SSH 后默认显示当前服务器文件；本机终端不建立远程文件连接。
- 多终端分屏时，侧栏跟随当前聚焦的终端。
- 每个会话分别保存当前目录、滚动位置和选择状态，不同服务器不能串目录。
- 文件路径栏、上一级、刷新、隐藏文件、上传、下载、新建、重命名、删除保留。
- 上传使用系统文件选择或 Finder 拖入，下载使用系统保存位置；不常驻整个本地文件浏览器。
- 普通文本默认交给外部编辑器；保留必要的下载、编辑、确认上传链路，限制自动打开的大文件。
- 路径跟随使用现有 Shell integration/CWD 事件，不能每秒向终端注入 `pwd`。
- 折叠停止不必要的目录刷新和 UI 工作，不能断开 SSH，也不能中断正在进行的传输。
- 可隐藏或卸载文件视图，但传输任务所有权不能绑在视图组件的挂载周期上。

后端 `src/app/server/session-sftp.js:56` 已复用当前 SSH 连接创建 SFTP 通道，建议保留这一点。
只关闭 SFTP 通道时不能误关共享 SSH 连接；SFTP 不受支持时明确显示状态，不能拖垮终端。

### 6.3 迁移体验

增加“MobaXterm 兼容”操作预设，但不包含用户明确不需要的选中复制、右键粘贴：

- 不启用选中自动复制、右键直接粘贴；保留常规复制粘贴和右键菜单。
- 多行或危险粘贴确认保留，不能为了相似而去掉安全保护。
- 接近其会话分组、双击连接、标签切换、重复会话、断开与重连操作。
- 支持常用的 `Ctrl+Tab`、`Ctrl+Shift+Tab`、`Ctrl+Shift+B` 等习惯。
- 在 Mac 上额外支持 `Cmd+C/V`；`Ctrl+C` 仍发送终端中断。
- 涉及 macOS 系统快捷键和 Option 字符输入冲突时允许配置，不盲目原样搬运全部 Windows 键位。

另做一次性的 MobaXterm 会话导入，输入以实际导出样本或 INI 文件为准，验证分组、主机、
端口、用户名、跳板机和私钥路径。当前 JSON 导入不能直接当作 MobaXterm 格式解析器。
Windows 私钥文件路径在 Mac 上需要重新选择；已保存密码不承诺无损迁移，不设计密码破解。

第一版不复刻其 X Server、Windows/Cygwin 工具、远程桌面和完整宏系统。
如果实际工作依赖 X11，需要单独决定保留 SSH X11 forwarding，并在 Mac 配置对应服务；
这不是一个 UI 换皮可以自动解决的问题。

## 七、资源占用：现状、测法与优化

### 7.1 当前没有可信的实测值

本次检查未发现正在运行的 electerm/electron 应用进程。
工作树尚无 node_modules、已构建应用和安装包；当前环境是 Windows，不是 M5 Mac。
因此不能把机器上其它 node 进程的内存算成 electerm，也不能伪造 Mac 的 CPU 或内存数字。

当前只能确认结构性开销与候选优化，收益必须在相同设备的正式构建中对比。

### 7.2 优先级

| 优先级 | 当前状态/候选开销 | 建议 |
| --- | --- | --- |
| P0 | 每个会话 fork 一个 session-server，并提供本地服务 | 先测 1/5/10 会话增量内存，保留隔离性；避免重连、关闭遗留进程 |
| P0 | 隐藏 SFTP 仍可能初始化本地/远程数据 | 远程单栏、按可见性初始化、取消未用请求，不读整个本机 home |
| P0 | AI、插件、同步和多协议模块仍在模块图/产物中 | 移除源码入口与依赖，检查构建产物；隐藏按钮不算完成 |
| P1 | 终端初始化加载搜索、序列化和字体连字插件 | 搜索首次使用再加载；序列化仅在启用历史恢复时加载；默认不加载连字 |
| P1 | 透明终端与背景滤镜路径 | 取消背景系统，使用不透明黑色；比较实际 CPU/GPU 与交互效果 |
| P1 | 大输出需要缓存和解析 | 保留现有输出合并/截断保护，增加发送队列与端到端背压评估 |
| P2 | 多会话子进程可能带来较高增量开销 | 有数据后再考虑小型 worker pool；不将所有会话贸然放进一个主进程 |

注意已有优化，不能重复计作新增收益：

- 默认渲染器已经是 DOM，不是每个会话默认开 WebGL。
- 隐藏终端已经有释放 WebGL 的生命周期处理。
- 远程监控栏默认关闭、光标默认不闪烁、scrollback 默认 3000 行。
- 前端 attach addon 已有约 2 Mi 字符缓冲限制；不能说它完全没有上限。
- 保存日志默认关闭，headless 终端解析器按日志功能需要创建。

DOM 和 WebGL 谁更省资源必须按输出负载实测，不能把关闭 GPU 当作普遍优化。
隐藏终端可以减少绘制，但仍需消费输出并保持终端状态，不能暂停网络读取导致远端程序阻塞。
每会话资源包括合法的 Shell/命令进程，要与泄漏的应用辅助进程区分。

### 7.3 测量方案

用原版与定制版的正式 ARM64 构建，关闭开发服务器和 DevTools，在同一台 M5 上分别测试：

- 冷启动到可输入、空窗口、本机终端、单 SSH、5/10 个 SSH。
- SFTP 展开/折叠、大目录、上传下载。
- 持续日志输出、vim/top 等全屏交互、快速切标签。
- 重复开关会话 50 次，稳定运行 8 小时。
- 前台、最小化、锁屏与睡眠恢复。

记录主进程、renderer、GPU、公共后端、每会话后端各自的 CPU、内存和进程数。
Electron 指标与系统进程树联合采样，不能漏算 fork 的会话进程。
记录空闲平均 CPU、负载峰值、输入响应、内存变化、冷启动耗时、DMG 与安装后体积。
统一内存口径，不能把全部 RSS 简单相加当成不重复计算的真实物理内存。

第一轮验收关注：空闲时无高频后台工作；侧栏折叠不继续刷新；关闭会话后进程和内存回落；
反复开关不持续增长；优化不引入丢输入、断线与渲染错误。
有基线后再约定具体 MB、CPU 和体积目标，不预先承诺降到几十 MB。

用户要求的性能底线：相同设备、会话、输出负载和功能状态下，定制版的稳态内存、平均 CPU、
进程数和启动耗时不得出现超出测量波动的回退。另行对比两版各自的日常默认配置，
避免用“原版 SFTP 展开、定制版折叠”掩盖默认常驻侧栏的实际开销。
每项多次采样；出现回退时先定位、调整或撤回对应实现，未达到底线不作为完成交付。

固定 SFTP 侧栏和断线重挂都不是零成本改动：应避免重复文件列表、重复终端实例、
无界输出缓存和高频健康轮询。重挂优先复用既有有界缓存，额外缓存有独立预算和超时回收；
折叠/非活动视图停止无用刷新，连接故障才启用退避重试，诊断日志采用限量与按需采样。
以上是实现与验收约束，不是已经获得的实测结果。

Electron 运行时不会因删除业务按钮而消失。如果实测仍达不到轻量目标，再单独评估原生方案；
那属于连接后端、文件传输、UI、凭据和打包体系的迁移项目，不是首版小改。

## 八、删除范围与必须保留的基础能力

建议从源码可达路径与依赖中移除：

- AI 聊天、Agent、AI 命令建议、AI 生成书签/主题。
- MCP 服务、外部终端控制接口。
- Widget 市场、插件运行时及内置文件/FTP/SSH 服务器插件。
- RDP、VNC、Spice、内嵌 Web 会话。
- 独立 FTP 客户端；Telnet/串口按首版严格范围退出。
- 云同步、Gist/WebDAV 同步和外部账号配置。
- 远程监控面板、监控轮询、自定义 watcher。
- 主题市场、复杂背景和透明度。
- 内置文件比较与重型编辑界面、批处理编排、触发器和复杂快捷命令管理。
- 赞助推广、云服务入口与上游自动升级入口。

相关候选依赖包括 `@novnc/novnc`、`ironrdp-wasm`、`spice-client`、`serialport`、
`basic-ftp`、`@electerm/ftp-srv`、`electerm-sync`、仅供删除功能使用的 Markdown/diff 渲染库。
逐项检查剩余引用和传递依赖，再更新 package.json 与 lockfile，不能只按名字删。

Zmodem/trzsz 属于终端传输扩展，不是绝对无关；本方案首版以 SFTP 为唯一文件传输方式，
建议裁掉其自动探测与依赖。如日常确实使用 rz/sz，再明确保留对应能力。

必须保留：

- SSH host key/known_hosts 验证、MFA、密钥和凭据保护。
- 最小必要 IPC 白名单、contextIsolation、token 验证。
- 基础本地会话导入导出，不能与云同步一起全删。
- 传输覆盖/删除确认、失败状态和安全路径处理。
- 崩溃与连接诊断日志，默认脱敏并有轮转/容量限制。
- 原许可证和必要归属说明；移除界面水印不等于删除 LICENSE。

移除内嵌 Web 会话后，再关闭 `webviewTag` 和删除对应 webview 处理路径。
现有值位于 `src/app/lib/create-window.js:69`。
非本机目标的构建流程不运行；删 CI 配置本身不会直接让应用内存变小。

## 九、MacBook M5 打包与分发

目标选择 `darwin-arm64`，不需要单独的“M5 架构”构建，也不以 Intel/Rosetta 包作为首选。
仓库已有 ARM64 流程：

- `.github/workflows/mac-arm.yml`：macOS 构建环境，Node 24。
- `src/build/bin/build-mac-arm.js:17`：ARM64 原生模块重建。
- 同文件 `:18`：`electron-builder --mac --arm64`。
- `src/build/electron-builder.json`：DMG、hardened runtime、entitlements 和 notarize 配置。

建议在 Apple Silicon Mac 或可用的 macOS CI 上执行最终构建、签名与公证。
当前 Windows 机器适合做源码开发和部分测试，不把它当作正式签名 Mac 包的最终环境。

新增专属极简版构建配置，不沿用上游发布账号或发布目标：

1. 使用独立的产品名、appId、数据目录和版本标识，先与原版并存。
2. 关闭上游自动更新，避免将定制版覆盖回原版。
3. 固定 Node/Electron/依赖版本，整理为可复现安装；现有 `prepare.js` 还会在 work/app 内重新 npm install，需要一并控制。
4. 保留仓库 build/prepare 阶段，在目标 Electron ABI 下重建 ARM64 `node-pty`。
5. 打包 ARM64 `.app`、DMG，可附 ZIP；只携带实际使用的资源与依赖。
6. 用定制版所有者的 Developer ID 签名，公证并 staple；凭据仅通过本地安全配置或 CI secrets 注入。
7. 自用未签名测试包与正式分发包分开配置；不通过关闭整机 Gatekeeper 作为安装方案。
8. 在 M5 真机检查架构、node-pty 启动、签名、公证和安装后首启。

现有构建命令可作为基线：

```sh
npm ci --legacy-peer-deps
npm run b
npm run pb
node src/build/bin/build-mac-arm.js
```

这是原仓库流程参考，不是本次已执行成功的命令，也不是未配置签名时保证可直接发布的方案。
正式实施时应另加显式、不上传上游的定制构建入口，再验证全部步骤。

## 十、实施顺序与交付标准

1. 基线：建立原版 Mac ARM64 包，采集资源数据与断连日志，准备现有会话数据备份。
2. 稳定性：修会话索引竞态、增加退出诊断，再分离显示通道与会话生命周期，补重挂测试。
3. 界面：纯黑背景、共享左侧 Sessions/SFTP dock、MobaXterm 操作预设与迁移入口。
4. 裁剪：先断开模块入口，再删后端服务、IPC、状态、资源和无用依赖，逐批跑回归。
5. 性能：前后同设备对比，按测量结果决定是否需要进程池等更深调整。
6. 发布：独立标识与升级路径、ARM64 包、签名公证、M5 真机长稳验收。

完成标准：

- 黑色背景无水印，不因配置迁移、重连或切换渲染器重新出现。
- 不再出现 AI、插件、云同步、远程桌面等入口，发布产物无对应可执行模块。
- 左侧 SFTP 收起不影响终端和传输；切服务器不串路径。
- 本地显示通道短断不会无条件杀死正常 Shell；远程真实断网有准确状态。
- 错误、主动退出与新建重连会话可区分，不伪装成原会话恢复。
- Mac ARM64 原生运行、关键快捷键可用、连接与传输功能回归通过。
- 不加入选中自动复制和右键直接粘贴。
- 同条件与日常默认配置的性能对照均完成，不接受未经解释和处理的资源占用回退。
- 提供实测 CPU/内存/体积对照和已知限制，不以按钮减少代替性能结论。
